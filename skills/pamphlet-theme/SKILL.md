# 挑一套 Pamphlet 主题

**按文档类型挑，不按好不好看挑。** 内置主题每套都是独立的配色**和版式**——正文宽度、标题体系、提示块形态、Tab 形态、表格线各不相同。

清单在 [themes.md](themes.md)（由源码生成，不会和代码对不上）。

## 怎么写

```bash
pamphlet build 方案.md --theme incident
```

或者写进源文档，让它跟着文档走：

```yaml
---
theme: incident
---
```

**`--theme` 压过 frontmatter。** 命令行是「这一次编译」的意图，frontmatter 是「这份文档一贯的样子」——一次性的意图应该能盖过长期设定。

名字写错报 `DOC-106`，**退回 `default` 继续编译**：主题错了只影响长相，内容是对的。诊断会一套一行地列出全部主题，每个名字后面跟着它适合写哪类文档。

## 常见体裁对应哪一套

| 你在写什么 | 用 |
|---|---|
| 拿不准 / 通用 | `default` |
| 小说、随笔、连续阅读的长文 | `fiction` |
| 技术文档、操作手册、代码为主 | `manual` |
| 需求文档、PRD、验收清单 | `prd` |
| 系统设计、架构方案、图多 | `architecture` |
| 详细设计、接口字段表、密度优先 | `blueprint` |
| 故障报告、复盘、时间线 | `incident` |
| 论文、研究报告 | `paper` |
| 对外发布、要好看 | `editorial` |
| 监控面板式、等宽高密度 | `console` |
| 只想要黑白灰 | `minimal` |
| 深色、等宽、技术风 | `tech-dark` |

判据是**这份文档是什么**。同一份内容换主题只改长相，一个字都不会变。

## 只想动一两个颜色

内置主题不够用时，往源文档里写一段 `<style>` 覆盖 CSS 变量——**裸 HTML 是原样通过的**，所以这条能生效。两条路可以叠加：先 `--theme paper`，再盖掉其中一两个值。

```markdown
<style>
  :root { --pf-primary: #7c3aed; }
</style>

# 我的方案
```

链接、Tab 的选中下划线、步骤的圆圈全部跟着变——它们的默认值都从 `--pf-primary` 派生。

**产物一律深色，不看读者的系统设置**，所以写在 `:root` 上的就该是深色的值。浅色只在打印时用得上：

```markdown
<style>
  :root {
    --pf-primary: #a78bfa;
    --pf-bg: #1a1614;
    --pf-fg: #ede4d8;
  }
  @media print {
    :root {
      --pf-primary: #7c3aed;
      --pf-bg: #fffbf5;
      --pf-fg: #2a2118;
    }
  }
</style>
```

全部变量见 [tokens.md](tokens.md)。**优先改语义层**：改一个，从它派生的一片跟着变；只想动某一处时才去改元素层。

## 三个代价，说在前面

- **这段 `<style>` 的权限没有任何限制**，能盖掉整个主题系统。写错一个变量名不会有任何提示
- **每份文档都要写一遍**。没有共享配置，源文档就是配置的全部载体。只换整套主题的话用 `--theme` 或 frontmatter，不必重复
- **变量名在 0.x 期间可能改**，没有承诺

## 每一套都守同一条底线

主题能改布局，但这四条对每一套一视同仁，有浏览器层测试逐套钉着：关掉 JavaScript 时两个 Tab 的内容都看得见；折叠块降级成原生 `<details>` 且内容还在；正文字号 ≥ 14px；有 JavaScript 时只显示选中面板且点得动。

所以**不要为了视觉效果去掉降级行为**——那是主题不能拿来换的东西。
