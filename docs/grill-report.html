01最有价值的部分：四处被事实推翻的原方案假设

这些不是意见分歧，是原设计文档里写着、但经查证不成立的技术判断。每一条都改变了后续的方案。

§2.2「Node 内 Mermaid + jsdom 即可预渲染，无需 Puppeteer」——不成立

Mermaid 组织成员当面否定：Mermaid 依赖真实浏览器的排版引擎计算尺寸与位置，jsdom 未实现 SVGTextElement.getBBox()，量不出文字尺寸就排不了版。 出处：mermaid#3886。

连带作废三处：技术选型表里「Mermaid 互操作零成本 ★★★★★」这个 TypeScript 加分项、「规避 45s 构建恶化」的论据、风险登记册里 R1 的等级。改后方案：走官方的 mermaid-isomorphic + Playwright（首次约 150MB Chromium），列为可选依赖 → ADR-0004。

§7.2:::tab 部署视图 | 成本视图 这个写法是非法的

原文档声称「沿用 micromark-extension-directive 风格」，但那个扩展的语法规定是 :::name[label]{attrs}，名字后面不允许跟没有括号包裹的自由文本。所以那一行解析不出来。 出处：官方 README。

改后方案：真嵌套、外层用更多冒号，零自定义语法 → ADR-0013。

FR-6「SVG 用 currentColor / CSS 变量，切主题不重编译」——对一半引擎不成立

Mermaid 的 themeVariables 不接受 var(--x)（sanitize 正则会清空非十六进制值，官方 open issue #6677、#6860），输出 SVG 里是硬编码颜色；Graphviz 把未知色名当错误处理。只有 MathJax v3 天然用 currentColor，d2 只能跟随系统亮暗。

改后方案：构建期后处理，把硬编码色替换成带兜底值的 CSS 变量 → ADR-0016。必要配套：golden 快照必须覆盖「每引擎 × 亮暗」，因为替换规则会随引擎升级静默失效。

§12「服务端 nonce 不可得时用 sha256」——「不可得」不是偶发，是必然

CSP 规范要求 nonce 每次响应唯一、由 CSPRNG 生成、至少 128 bit 熵。静态文件没有「每次响应」这个概念，写死即公开。所以哈希不是备选方案，是唯一方案。

顺带查明另外两条：运行时不能用 <script type="module">（module script 按规范走 CORS 抓取，file:// 无 origin，双击打开直接失效）；Service Worker 在 file:// 完全不可用 → ADR-0017。

顺手撞到一个调研没提的坑：subset-font 不吃 .ttc 字体集合文件（Error: Unrecognized font signature: ttcf）。底层 harfbuzz 支持按序号选字面，但这个 JS 包没暴露那个参数 ⇒ 作者给 .ttc 时编译器必须先拆出单个字面。原文档没算这一步。

引擎体积：实测 189MB，比我原先的推测高

六个 npm 引擎装完 270 个包、189MB（d2 的 WASM 60MB、mathjax-full 42MB）。加 Playwright + Chromium 约 150MB ⇒ 全装约 340MB。顺手砍掉约 38MB：canvas（19MB，还是需要本地编译的原生模块）和 @jimp/gifwrap/@resvg 全是光栅图输出用的，而 Pamphlet 只要 SVG——改用库而非命令行包即可全部消掉 → ADR-0008。

05明知并接受的四处风险敞口

这些不是遗漏，是你在权衡后选的。写死在 ADR 里，将来不会被当成 bug 修掉。

一段 <style> 可以盖掉整个主题系统

裸 HTML 完全原样通过，而 style-src 'unsafe-inline' 是 CSP 唯一的松口。最常见的来路是从别处复制粘贴带 style 的 HTML 片段。若日后要收紧，第一个该收的就是 style 属性——收益最大、对作者损失最小。

SVG 有两条待遇不同的路径

引擎产出的 SVG 被严格消毒，作者手写的内联 SVG 完全不受约束（可带 SMIL）。代码里必须写清「消毒只作用于引擎产出的 SVG」，以免将来有人误以为「所有 SVG 都消毒过」而基于此做别的决定。

通配符不做任何默认排除

pamphlet build "**/*.md" 在装了依赖的仓库里会编译上百个第三方 Markdown，而产物写在源文档旁边 ⇒ HTML 散落进 node_modules。唯一防线是文档。

超时 30 秒 ⇒ 最坏反馈时间很长

正常渲染是百毫秒级，30 秒是三百倍；十张图全卡死时双核机器最坏等五分钟才报失败。缓解只有 --timeout。这个数字没有实测依据。

06下一步：可以直接开工的顺序

范围是「P0 一个都不砍」，人力是一人 + AI，顺序是水平分层，节奏是每 2 周一个 alpha。
