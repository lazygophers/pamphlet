# 未闭合的指令是错误，不自动闭合

源文档里有未闭合的 `:::` 时报错（`DIR-2xx`），不产出 HTML。原始设计里「在文档末尾自动闭合并给警告」的做法不采用。

## 为什么改

[0013](./0013-tab-syntax-is-nested-directives.md) 定了 Tab 用真嵌套、外层用更多冒号（`::::tabs` 里套 `:::tab`）。嵌套之后「自动闭合」从一个便利变成了一个**猜测**——作者少写了一个 `:::`，编译器无法判断是内层没闭合还是外层没闭合，两种猜法会产出结构完全不同的文档。

而猜错的后果是：编译成功、产物看起来正常、但内容结构和作者意图不同。这正是本项目反复用来否决方案的那一类问题（见 [0010](./0010-reject-newer-spec.md)、[0028](./0028-failed-diagram-produces-artifact-but-fails-build.md)）。

## Consequences

诊断必须给出**未闭合的那个指令的起始位置**，而不只是「文档末尾发现未闭合」——后者对一份有二十个指令的文档毫无帮助。理想的诊断同时指出开启处和期望的闭合冒号数。

单个未闭合的指令会让整份文档编译失败，这对写作过程中的中间状态不友好（正在写一半）。缓解手段是 `pamphlet serve` 的快速反馈：改一个字就重编译，所以未闭合状态通常只存在几秒。
