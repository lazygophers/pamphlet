# 脚注报错，不静默吞掉

用了 GFM 脚注（`[^1]` 加 `[^1]: 注释`）报 **`DOC-105`**，严重程度 `error`。引用和定义**各报一条**，孤立的定义也报。

```
error[DOC-105] 本版本不支持脚注
  --> 方案.md:3:4
  = 改写成正文里的括注，或用 :::info 容器承载注释
```

检测点在 `packages/pamphlet/src/parse.ts` 的 `validateTree()` 里，和指令校验同一层。

## 原来是什么样

`parse.ts:35` 打开了 GFM，所以脚注**会被解析出来**。但 `assemble/html.ts` 没有 `footnoteReference` / `footnoteDefinition` 分支，两个节点都掉进 `html.ts:172-175` 的 default：

- 引用节点没有子节点 → 渲染成空字符串，`[^1]` 那个上标**凭空消失**
- 定义节点有子节点 → 正文被原地插进文档流，「注释」两个字混进正文

**全程没有任何诊断。** 编译器认为一切正常，退出码 `0`。

这是所有失败形态里最坏的一种：作者不会发现，读者拿到的是一份缺字且多字的文档。

## Considered Options

- **直接实现脚注渲染**（补两个分支，渲染成带跳转的上标 + 页脚列表）：约 2 小时。落选——不是不该做，是顺序问题。让丢内容变得可见，比让它可用更急。
- **降级成 `warning`**：不挡构建。落选——警告默认不改变退出码，CI 会绿，等于没治。内容会丢的事必须挡住。
- **只在引用上报一条**（不报定义）：噪音更小。落选——孤立的定义（写了 `[^1]:` 但没引用）同样会把正文插进文档流，不报就漏了。

## Consequences

**`DOC-1xx` 段多了一个码，总数从 19 变 20。** 码表页 `reference/diagnostics.md` 同步加了 `DOC-105` 小节，`DOC_BASE` 的锚点规则不变。

**行内脚注不受影响。** Pandoc 的 `^[注释]` 不属于 GFM，解析器把它当普通文字，不丢内容也就不报。测试里显式钉住了这条，防止以后有人「顺手」把它也拦掉。

**将来实现脚注时，这条诊断要一起删。** 它是一个明确的临时物：`DOC-105` 存在的全部理由就是「解析得出来但组装不了」，那天不成立了它就该消失。

**六条单元测试钉住了行为**（`packages/pamphlet/test/parse.test.ts`）：引用+定义各一条、严重程度是 error、带 hint、孤立定义也报、位置落在脚注那一行、不含脚注的文档零诊断。
