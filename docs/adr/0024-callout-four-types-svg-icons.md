# 四种提示块，各自一个指令名，图标用内联 SVG

四种提示块：`info` / `tip` / `warn` / `danger`，**各自是一个独立的指令名**：

```markdown
:::warn
注意幂等性。
:::

:::tip[顺便说一句]
标题可选，写在方括号里。
:::
```

语义层因此有对应的四个颜色 token（见 [theme-tokens.md](../theme-tokens.md)）。

「callout」仍然是这一类块的统称（见 CONTEXT.md 的术语），但它**不是指令名**。

图标用内联 SVG，从一套 MIT 或 CC0 授权的线性图标库（如 Lucide、Heroicons）里挑四个，**只取需要的那四个，不引入整个库**。每个约 200-400 字节，四个都用上不到 2KB。

## Considered Options

原始设计写的 `:::callout warn` 在语法上是非法的——名字后面不允许跟没有括号包裹的自由文本（见 [0038](./0038-directive-syntax-rules.md)）。所以「类型怎么写」必须重定：

- **`:::callout{type=warn}`**：只有一个指令名要记，将来加第五种类型不必新增指令名。落选——每次都要多打十个字符，而这是技术文档里最高频的扩展语法之一；而且「忘了写 type」需要一条专门的诊断。
- **`:::callout{.warn}`**（class 简写）：比 `{type=}` 短。落选——class 在语义上是「样式类」而不是「这是哪种提示」，且点号对不熟悉 CSS 的作者很陌生。
- **四个指令名 + 保留 `callout` 作为别名**：迁移最平滑。落选——同一件事两种写法，团队里会混用；[0019](./0019-fence-names-are-engine-native.md) 当初否决图表围栏别名的理由在这里同样成立。

采用四个独立指令名的理由：最短（`:::warn` 比 `:::callout{type=warn}` 少十个字符）；是这个领域的通行写法（Docusaurus 用 `:::warning`，作者的肌肉记忆能直接用上，和 [0019](./0019-fence-names-are-engine-native.md)「跟着生态走、不自造」同一条思路）；标题落在标准的 `[label]` 位置，与 `:::tab[部署视图]` 完全一致。

其余落选项：

- **只做原始设计的三种**（`info` / `warn` / `danger`）：语义层不用加色。落选——技术文档里「顺便说一句」和「警告」语义完全不同，只有三种时作者会拿 `info` 表示两种不同的东西。
- **图标用 emoji**：零字节、零选型、零授权问题。落选——同一个 ⚠️ 在 Windows、macOS、Android 上渲染差异很大（彩色三角 / 黑白线框），而产物是要发给别人打开的文件，视觉一致性在这里比省 2KB 重要。[0011](./0011-no-size-gate.md) 取消体积卡点之后，2KB 不构成约束。
- **不做图标，只用左边框和底色区分**：最简洁，颜色全部来自 token。落选——四种 callout 只靠颜色区分对色盲读者无效，与无障碍要求冲突。

## Consequences

图标是静态 SVG 片段，直接内联进产物，不属于运行时（[0012](./0012-runtime-assembled-not-bundled.md) 的六个特性片段不受影响）。

只有用到的类型才内嵌对应图标——一份只有 `warn` 的文档不该带上另外三个图标。这与运行时按特性裁剪是同一条原则。

图标库的授权必须记进依赖清单。取四个图标而非整个库，是为了避免「为了 2KB 引入一个几百 KB 的依赖」。
