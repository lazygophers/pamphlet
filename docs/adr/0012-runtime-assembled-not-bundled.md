# 运行时按特性拼接，编译期不跑打包工具

`@pamphlet/runtime` 在**它自己发布时**就被构建成一个约 1KB 的事件委托内核加六个互相独立的特性片段（Tab 切换、折叠、步骤揭示、滚动动效、主题切换、图表 pan/zoom）。编译一本 pamphlet 时，编译器扫一遍 AST 得出用到了哪些特性，然后把内核和对应片段**字符串拼接**后内嵌进产物。编译期不调用任何打包工具。

## Considered Options

- **编译期调用 esbuild / rolldown 做 tree-shaking**：运行时内部可以自由共享工具函数，由打包工具算出该保留什么。落选：它把一个打包工具变成运行时依赖（几十 MB），且每次编译都要跑一次打包，与「增量构建 < 500ms」抢时间。
- **不裁剪，永远内嵌全部六个特性**（约 20KB gzip）：最简单，一个固定字符串、没有静态分析、没有六种组合要测。落选。

## Consequences

**编译一本 pamphlet 的机器上不需要有打包工具**，编译器在这一步只做字符串拼接。这是本决定最大的收益，尤其对「双击就能用」这个定位——工具链越短越好。

**六个片段不能共享代码**，否则拼接会漏掉被依赖的部分。这看起来是限制，实际是有用的约束：它逼着每个特性真正独立，而这六个特性本来就互不相关。任何将来「两个特性想共用一段逻辑」的需求，答案是把那段逻辑放进内核，而不是让片段之间互相引用。

测试面变成「内核 + 六个片段的组合」。不需要测全部 64 种组合：片段互相独立意味着逐个测 + 测一次全集即可。
