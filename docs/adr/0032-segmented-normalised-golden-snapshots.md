# golden 快照分段存储并归一化

一份产物拆成四段，各存一个快照文件：

1. `<head>` 里的 CSP 与主题变量
2. 正文 HTML
3. 每张图的 SVG（单独一份——这是 [0016](./0016-diagram-theming-by-post-processing.md) 要盯的那份）
4. 运行时片段清单（只记用了哪几个特性，不记内容）

比对前先归一化，把不稳定内容替换成**带信息的**占位符：

| 原内容 | 占位符 |
|---|---|
| 字体子集的 base64 | `[FONT:woff2:1480glyphs]` |
| CSP 里的运行时哈希 | `[SHA256]` |
| 源文档内嵌的 base64 注释 | `[SOURCE:2481bytes]` |
| 图片 data URI | `[IMG:png:140KB]` |

## 为什么必须这么做

直接把整份产物 HTML 存成快照会当场失效，三个具体原因：

1. **字体子集是 base64**——一份内嵌字体的产物里有几十万字符的 base64（实测一份带真实中文字体的探针页 572KB），快照 diff 完全不可读。
2. **CSP 里的运行时哈希**（[0017](./0017-strict-csp-in-artifact.md)）——运行时内容一变哈希就变。
3. **源文档内嵌**（[0014](./0014-embed-source-in-html-comment.md)）——产物末尾那条 base64 注释，源文档改一个字整段就变。

## Considered Options

- **整份 HTML 一个快照，只做归一化**：一份产物一个文件。落选——任何一处改动都让整份快照变，diff 里要在几千行中找那一处。
- **不存 HTML，只存关键断言**（图的节点数、CSP 字符串、片段清单）：文件小、无噪音。落选——只能发现你想到要断言的东西，而 golden 快照的价值恰恰在于发现**没想到**的变化（例如某次升级让 SVG 里多出一个 `<style>`）。
- **分段但不归一化，把带字体和图片的用例排除在快照之外**：不用写归一化层。落选——「内嵌字体」和「内嵌图片」这两条路径失去保护，而它们恰好最容易出问题。

## Consequences

diff 变得可读且定位精确：改一行 CSS 只有第 1 段变，升级 Mermaid 只有第 3 段变——而第 3 段正是 [0016](./0016-diagram-theming-by-post-processing.md) 要盯的。那份 ADR 明确记了「颜色替换规则会随引擎升级**静默失效**」，golden 快照是唯一能发现它的手段，所以快照可读是这道防线能成立的前提。

占位符带信息而非留空，所以「字体从 1480 字变成 1500 字」这类变化仍然会被发现。

归一化层本身需要测试——它只有几十行，但如果它错了，整道防线会安静地失效。
