# 源文档以 base64 存进一条 HTML 注释

产物末尾输出一行 `<!-- pamphlet:source v1 <base64> -->`，装整份源文档。`extract` 命令找到这一行、解码、写文件。默认开启，`--no-embed-source` 可关。不再逐张图单独内嵌图源——图源本来就在源文档里。

## Considered Options

- **用 `<script type="application/pamphlet">` 标签存**：结构上更正式，且产物内的 JavaScript 理论上能读到源文档（例如做一个「查看源码」按钮）。落选：未知类型的 script 标签虽然不会被执行，但它是否需要写进 CSP 的允许清单需要额外实测，而没有任何需求需要浏览器端读到源文档。
- **原始设计的两种并用**（逐图 base64 注释 + 整份源文 script 标签）：信息最全但重复存储、体积更大、两处格式都要维护版本号。落选。
- **默认关闭，需要时用 `--embed-source` 开**：产物最小最干净。落选，因为「源文档丢了想从 HTML 捞回来」这个场景恰恰是事后才发现的，默认关等于这个功能在最需要它的时候不在。

## Consequences

HTML 注释是产物里唯一「保证不被执行、不被 CSP 管、不被消毒器碰」的容器，因此这个决定不给安全边界增加任何新的解释负担。

代价是体积：base64 编码膨胀 33.3%（RFC 2045 §6.8、RFC 4648 §4），所以一份 100KB 的源文档会在产物里占约 133KB。这个代价被接受，因为 [0011](./0011-no-size-gate.md) 已经把体积判断权交给作者，且 `--no-embed-source` 提供了出口。

注释里带 `v1` 版本标记，是为了将来改变编码方式时 `extract` 能识别旧产物。
