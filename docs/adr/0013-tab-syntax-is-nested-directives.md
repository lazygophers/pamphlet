# Tab 用真嵌套指令，不自造语法

一组 Tab 写成嵌套的容器指令，外层用四个冒号：

```markdown
::::tabs
:::tab[部署视图]
内容一，可以放图表。
:::
:::tab[成本视图]
内容二。
:::
::::
```

原始设计写的 `:::tab 部署视图 | 成本视图` **在语法上是非法的**，必须改。

## Considered Options

原始设计声称「沿用 micromark-extension-directive 风格」，但那个扩展的语法规定是（<https://github.com/micromark/micromark-extension-directive>）：三种指令 `:name[label]{attrs}` / `::name[label]{attrs}` / `:::name[label]{attrs}`；`name` 必填（字母数字加 `-` `_`）；`[label]` 与 `{attrs}` 均可选；**名字后面不允许跟没有括号包裹的自由文本**；容器嵌套靠「外层用更多冒号」，闭合栅栏的冒号数要 ≥ 开启的。因此 `部署视图 | 成本视图` 不在任何合法位置上。

- **单层加属性** `:::tabs{titles="A|B"}`，面板用 `---` 分隔：只用三个冒号，但标题与内容分离（加一个 Tab 容易错位），而且给 CommonMark 的分隔线 `---` 赋予第二个含义——这违反「超集不背叛」。落选。
- **单层加独立指令做分隔** `:::tabs` 内用 `::tab[标题]`：写起来最短，但把「独立指令」当分隔标记用，解析出来是平坦列表、要靠编译器重组，且嵌套需要额外规则。落选。
- **自己扩展解析器**让原写法合法：作者写起来最自然，代价是从标准 directive 语法的使用者变成它的分叉——扩展升级要自己跟、别人的 Markdown 工具行为不可预期、标题里含 `|` 还要设计转义。落选。

## Consequences

零自定义语法。[0002](./0002-source-extension-is-md.md) 沿用 `.md` 的全部理由是逃生兼容，而逃生兼容的前提就是不偏离生态标准——偏离越少，别人手上的 Markdown 工具越不容易被搞糊涂。

「Tab 里可以放任何东西，包括另一组 Tab」是免费得到的，因为结构就是真实的嵌套。代价是嵌套时冒号数要继续往上加（Tab 里放折叠块，外层就是五个冒号）。

四个冒号的怪异感是一次性的学习成本，必须在语法手册的第一个 Tab 示例里就解释清楚「为什么外层多一个冒号」。
