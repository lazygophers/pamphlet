# 图表既有自有的结构化写法，也保留引擎原生的围栏名

**这份 ADR 在 2026-09-11 被推翻过一次，并且是原地改写的。** 仓库的惯例是新写一份而不是改旧的，这一次由维护者明确要求改这一份；原先的结论和它的理由完整保留在下面「原先的决定」一节里，不删。

## 现在的决定

图表有两种写法，**永久并存**：

1. **自有的结构化写法**：容器指令 `:::flow` / `:::sequence` / … 共十七种，指令体是「声明块 + 关系块」两段，关键字用英文（`nodes:` / `edges:` / `participants:` / `messages:` …）。十三种翻译成 Mermaid 图源后交给现有的图表管线；泳道图、网络拓扑图、数据图表、组织架构图这四种 Mermaid 画不了，自己算布局、自己出 SVG。
2. **引擎原生的围栏名**：` ```mermaid ` 照旧可用，行为一个字都没变。

自有写法是**推荐写法**，不是唯一写法。

## 为什么推翻原先的结论

- **有四种图 Mermaid 根本给不了**：泳道图、网络拓扑图、组织架构图它没有；柱状/折线图有 `xychart-beta`，但它的颜色算自主色、既不是哨兵又躲过替换，每次都报 `DIAG-304`。这四种不自研就永远做不出来，和「少打几个字」那种便利完全不是一回事。
- **结构化写法解决的不是名字，是结构**。原先否决的是「`seq` 当 `mermaid` 的别名」——那确实只换了个名字。现在这套换的是**指令体的组织方式**：字段名不同、骨架相同，学会一种就会十七种。
- **逃生兼容没有丢，只是不再是唯一的路**：` ```mermaid ` 永久保留，已经写好的文档一个字不用改，会 Mermaid 的人直接上手。

## 放弃了什么

- **自有写法在 GitHub 上不渲染**，显示成一段普通文字。这是明知的代价：要 GitHub 也能看的图，继续写 ` ```mermaid `。
- **同一件事有两种写法**。原先否决别名时的头号理由就是这个（团队里会混用），现在接受它——代价由「不强迫已有文档迁移」抵掉。

## 原先的决定（2026-09 之前，已被上面推翻）

> 图表围栏的语言名就是引擎自己的名字：`mermaid` / `d2` / `dot` / `vega-lite` / `wavedrom` / `bytefield` / `plantuml`，加一个 `math`（MathJax 没有「原生围栏名」的惯例，所以这个名字是唯一的名字而非别名）。
>
> 原始设计里的自有短名 `seq` / `flow` / `state` 全部删除。写时序图就是 ` ```mermaid ` 里面写 `sequenceDiagram`——和在 GitHub、Notion、VS Code 里写 Mermaid 完全一样。（`arch` 更早就因为内置 d2 而删除，见 [0008](./0008-builtin-engines.md)。）

### 它当初考虑并否决的两条路

- **保留 `seq` / `flow` / `state` 作为别名**：作者可以少打几个字。落选：同一件事有两种写法（团队里会混用）、要维护别名到引擎的映射表、别名在 GitHub 上不渲染，而且 `flow` 该映射到 Mermaid 的 `flowchart` 还是 d2 本身就是个需要决定并解释的问题。
- **全部走自有短名、把引擎名藏起来**（`seq` / `flow` / `arch` / `chart` / `wave` / `bits` / `uml`）：语言表面最整齐，将来换引擎不影响源文档。落选：彻底放弃逃生兼容，而且作者写图源时仍然必须懂那个引擎的语法——「隐藏引擎」只隐藏了名字，没有隐藏复杂度。

### 那两条理由现在还成立吗

| 原先的理由 | 现在 |
|---|---|
| 同一件事有两种写法，团队里会混用 | **仍然成立**，被接受了。代价换来「已有文档不必迁移」 |
| 别名在 GitHub 上不渲染，[0002](./0002-source-extension-is-md.md) 选 `.md` 的理由就白费了 | **部分成立**：自有写法确实不渲染，但 ` ```mermaid ` 保留，逃生兼容这条路还在 |
| 「隐藏引擎」只隐藏了名字，没有隐藏复杂度 | **不再成立**：结构化写法换掉的是指令体的组织方式，不是围栏名；而且那四种自绘图根本没有引擎可隐藏 |

## Consequences

- 十七种图共用一副骨架，新增第十八种时只加一个翻译器，解析和渲染管线不动。
- 翻译器是纯函数（结构进、文本或 SVG 出），可以脱离浏览器单独测。
- 十三种走 Mermaid 的图和围栏写法**共用同一条管线**：同一套缓存、同一套换色、同一套失败占位、同一条体积警告。
- 那四种自绘图用的是同样的六个 `--pf-diagram-*` 变量，所以换主题时和别的图一起变。
