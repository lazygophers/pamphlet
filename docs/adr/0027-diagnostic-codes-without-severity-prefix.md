# 诊断码不编码严重程度

诊断码只表示「是哪一类问题」：`DOC-101` / `DIR-201` / `DIAG-301` / `EMB-401`。严重程度是独立字段，终端输出时显示在方括号外面：`error[DIAG-301]`。原始设计里的 `E-` / `W-` 前缀去掉。

严重程度可以被配置改变（例如 `--fail-on-warn` 把所有警告当错误）。

## Considered Options

- **保留 `E-DOC-1xx` / `W-DIR-2xx`**：从码上一眼看出严重程度。落选——某个警告将来要升级成错误时，码得从 `W-DIR-201` 变成 `E-DIR-201`，而那个码已经被人写进 CI 脚本和文档链接了。严重程度可配置时它还会自相矛盾：一个 `W-` 开头的码在 `--fail-on-warn` 下表现为错误。
- **不用编码，只用可读规则名**（`unknown-directive` / `engine-not-installed`）：自解释、不用查表。落选——名字更长，且中文文档里「是否翻译规则名」本身是个麻烦；改名和改码一样破坏兼容。

主流做法佐证：TypeScript 的 `TS2345`、ESLint 的规则名都不编码严重程度；Rust 的 `error[E0308]` 里那个 E 是历史包袱。

## Consequences

`CFG-5xx` 这一类随配置文件的删除一并消失（见 [0030](./0030-frontmatter-only-configuration.md)）。

已经写进别处 ADR 的旧码已同步改掉（[0010](./0010-reject-newer-spec.md) 的 `DOC-101`）。当前码段划分：`DOC-1xx` 文档与语法、`DIR-2xx` 指令、`DIAG-3xx` 图表引擎、`EMB-4xx` 资源内嵌。

码一旦出现在错误消息里就会被写进 CI 脚本和文档链接，因此码的分配必须只增不删——即使某个诊断被移除，它的码也不再复用。
