# `{.interactive}` 只做 pan/zoom，不引入运行时图表渲染

标注 `{.interactive}` 的图仍然是编译期预渲染的静态 SVG，只是额外获得拖动与缩放能力（约 3KB 自研运行时，作用在 SVG 元素上）。原始设计里「interactive 图走运行时渲染、打包 Mermaid 子集」这条被删除。因此产物里只有一份图，不做「预渲染静态版 + 运行时版」的双份输出。

## Considered Options

- **打包 Mermaid 运行时到浏览器**：图可以在浏览器里现场渲染，支持点节点展开详情、动态改数据。代价是产物增量数百 KB 到 1MB+、`@pamphlet/runtime` 要维护第二条渲染路径、必须做双份输出（同一张图在产物里存两遍）、还要处理浏览器端渲染失败的兜底。落选。
- **完全不做 `{.interactive}`**：产物最小、只有一条渲染路径。落选，因为大架构图在手机上看不清，而「图表缩放不糊」是明确的用户故事。

## Consequences

这个决定消掉了整条第二渲染路径：不把图表引擎打进浏览器包、不做双份输出、不需要运行时渲染失败的降级逻辑。「产物零图表 JS」这条承诺因此完整成立——3KB 的 pan/zoom 是通用 SVG 操作，不是图表引擎。

无 JavaScript 时的降级变得平凡：一张不能拖动的静态图，内容完整可读，不需要占位提示。

代价是 `{.interactive}` 的语义被收窄了。「点击节点展开一个详情面板」这类需求本决定不支持；原始设计的开放问题里本来就把它列为「当前保守排除」，本 ADR 把它变成明确的边界。要放开需新开一份 ADR 取代本篇。
