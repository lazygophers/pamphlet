# 编译目标只能显式传路径，不支持 include / exclude 配置

`pamphlet build` 必须显式给出要编译的文件：`pamphlet build docs/方案.md`。不提供 `include` / `exclude` 配置字段，不带参数时不猜任何默认值。

**可以传多个路径，也可以传通配符，通配符由 Pamphlet 自己展开**（不依赖 shell）。多文件时任一失败则退出码为 1；`--continue-on-error` 时继续编译剩下的，把失败汇总在末尾。

## Considered Options

- **配置里的 `include` / `exclude` 清单**，不带参数时读配置，两者都没有时报错：编译一批文档时最省事，且可以隐式排除 `node_modules`。落选。
- **不带参数时默认编译当前目录下所有 `.md`**：开箱即用。落选——会把 `README.md`、`CHANGELOG.md` 以及依赖目录里的第三方 Markdown 一起编译，产出一堆没人要的文件。

## Consequences

编译器不猜任何东西，行为完全可预期。这和「源文档不需要任何身份标记、纯 Markdown 也能正常编译」是一致的：既然任何 `.md` 都是合法输入，那「编译哪些」就必须完全由调用方说清楚，不能由编译器推断。

**通配符由 Pamphlet 自己展开**，这避开了一个真实的坑：不同 shell 对 `**` 的支持不一致（`zsh` 原生支持递归匹配，`bash` 需要先 `shopt -s globstar`，否则 `docs/**/*.md` 只匹配一层），否则 CI 里会出现「只编译了一部分文件却没有任何报错」——那比报错更难发现。自己展开的代价是要在文档里说明「路径需要加引号」，否则 shell 会先抢着展开一遍。

**不做任何默认排除。** 通配符匹配到什么就编译什么，编译器不隐藏任何决定。这一条是明知代价的选择：`pamphlet build "**/*.md"` 在一个装了依赖的仓库里会命中 `node_modules` 下成百上千个第三方 Markdown，而产物写在源文档旁边（见 [0026](./0026-cache-in-tmpdir-output-beside-source.md)），于是那些 HTML 会散落在依赖目录里。**文档必须在通配符的第一个示例旁边就写明这一点**，并给出正确写法（`pamphlet build "docs/**/*.md"` 而不是 `"**/*.md"`）——这是本决定唯一的防线。

不读 `.gitignore`：那个文件说的是「什么不要提交」，与「什么不要编译」是两件事。混用会产生静默的意外——例如有人因为产物在 `docs/` 里而忽略了整个目录，源文档也一起不编译了。

多文件带来「部分成功」这个状态，因此：

- 退出码默认任一失败即 1（已产出的产物仍然留在磁盘上）；`--continue-on-error` 时继续编译剩余文件，退出码仍按是否有失败决定。
- **诊断按文件分组**，每组带文件头；末尾**固定打印**一行汇总（哪怕全部成功——静默的成功会让人怀疑它到底跑了没有），失败的文件名在汇总里单独列出，不必回上面的诊断里翻找。
- `--verbose` 的体积报告逐份输出，末尾给一个合计。
