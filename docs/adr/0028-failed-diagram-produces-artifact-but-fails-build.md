# 图表渲染失败：照样产出产物，但退出码为 1

一张图渲染失败或超时时：**产物照样生成**，那张图的位置是一个占位框，框里写着出错原因和原始图源；**但退出码是 1**，构建视为失败。显式加 `--allow-failed-diagrams` 时退出码变 0。

单图 SVG 过大给警告 `DIAG-302`；渲染超时报 `DIAG-303`。

## Considered Options

- **产出占位框、退出码 0**（原始设计的做法）：编译永不因单张图失败，流程最顺。落选——CI 会绿、作者可能直接把带占位框的产物发出去，而这正是 [0010](./0010-reject-newer-spec.md) 明确要避免的那种「看起来正常但内容是错的」产物。
- **任何一张图失败就中断整篇编译，不产出 HTML**：绝不产出有缺陷的产物。落选——本地写作体验很差：一张图语法写错，整份文档都看不到，而作者可能正想看别的部分。
- **退出码 1 且不产出正式产物，占位框只写进 `--debug` 产物**：正式产物永远干净。落选——多一条产物路径要维护，且作者要记住加 `--debug` 才能看到出错的图。

## Consequences

这是 [0010](./0010-reject-newer-spec.md) 那条原则的正确应用方式：原则不是「拒绝产出」，而是**「不谎报成功」**。两件事因此分开——产物是给人看的（能立刻定位哪张图挂了），退出码是给机器看的（不会把有缺陷的构建当成功）。

占位框里必须同时有出错原因和原始图源，否则作者要回源文档里对照才能知道是哪一张。

`--allow-failed-diagrams` 的存在是必要的：确实存在「先发一版、那张图待补」的真实场景，而让人用 `|| true` 绕过退出码比给一个显式开关更糟。
