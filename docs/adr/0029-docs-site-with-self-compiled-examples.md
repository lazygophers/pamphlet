# 文档站用常规站点生成器，示例产物由 Pamphlet 自己编译

Pamphlet 自己的语法手册与文档站用常规多页站点生成器（VitePress）。但每一页的语法示例旁边链一份**由 Pamphlet 真实编译出来的**单文件 HTML，这些示例产物在 CI 里重新编译，**编译失败就构建失败**。

（这说的是 Pamphlet 项目自己的文档，不是产品功能——产品仍然只做单文件，不做站点。）

## Considered Options

- **完全自举**：文档就是若干个 Pamphlet 单页 HTML，最彻底的狗粮、最好的能力展示。落选——产品不做多页站点，所以没有全局导航和搜索，外部开发者查一个语法要先猜它在哪一页；而且要等到编译器能出 HTML（约第 8-9 周）才能开始写。
- **只做常规文档站，示例用手写 HTML 片段模拟**：最快。落选——手写示例不会因为实现变了而失效，于是文档慢慢变成谎言，这是开源项目最常见的死法之一。
- **只写一份 README + 一份语法手册 Markdown**：成本最低，且因为源文档沿用 `.md`（见 [0002](./0002-source-extension-is-md.md)），手册本身在 GitHub 上就能渲染 Mermaid 示例。落选——没有搜索，长手册在单个文件里难以导航。

## Consequences

**文档成为一层免费的集成测试。** 这一点尤其重要：[0016](./0016-diagram-theming-by-post-processing.md) 明确记了「颜色替换规则会随引擎升级静默失效」，而 CI 里重新编译全部示例正好能兜住这类问题——比专门写一批测试用例更贴近真实用法。

文档站从第 2 周就能开始写，不必等编译器产出 HTML。这与「前 8 周的 alpha 只发语法与解析器」的安排相容：那段时间文档里的示例可以先只展示语法与 `lint` 输出，等编译器能出 HTML 后再补上「查看编译结果」的链接。

代价是维护两套东西（站点本体 + 示例源文档）。缓解方式是站点里的每个示例都直接引用示例源文档文件，而不是把源码复制进 Markdown——复制会让两者脱节，那就回到落选项的老问题上了。
