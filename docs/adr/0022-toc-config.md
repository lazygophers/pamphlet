# 目录：默认跳过 Tab 标题，P0 只做正文开头一种位置

```yaml
toc:
  enable: true
  deep: 2          # 收到几级标题
  skipTabs: true   # 默认 true：目录跳过 Tab 生成的那些标题
  position: top    # top（正文开头，纯静态）| side（粘性侧边栏，P1）
```

P0 只实现 `top`：目录是正文开头一段普通的嵌套列表加锚点链接，零 JavaScript、不新增运行时特性片段。`position: side` 在 P0 给出「该值尚未实现」的诊断，而不是静默忽略。

## 为什么需要 `skipTabs`

[0015](./0015-tab-titles-are-real-headings.md) 为了无障碍与深链，把 Tab 标题渲染成真实的标题元素（层级 = 最近祖先标题 + 1）。那个决定是对的，但它注定让 Tab 标题进入文档大纲——`deep: 2` 时天然被排除，`deep: 3` 时就会混进目录。

而 Tab 面板在语义上是同一话题的几种视角，出现在目录里会让读者误以为它们是不同章节。所以目录这一侧必须有对应的开关，默认关掉它们。

## Consequences

`position` 现在就写进配置格式、但只实现一个值，是为了将来加侧边栏时不必改配置格式。侧边栏本身是这一块里工作量最大的部分：响应式布局 + 滚动监听 + 窄屏折叠 + 一个新的运行时特性片段（[0012](./0012-runtime-assembled-not-bundled.md) 的六个特性会变七个）。

`position: side` 报「尚未实现」而不是静默降级为 `top`，遵循的是同一条原则：明确报错优于悄悄做别的事。
