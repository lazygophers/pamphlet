# `:::steps` 编译成原生有序列表，编号交给浏览器

`:::steps` 里的有序列表编译成 `<ol><li>`，编号由浏览器自己算。CSS 用 `::marker` 或 `counter()` 把默认的「1.」做成带底色的圆圈。滚动揭示动效按 [0005](./0005-css-only-animation-strict-svg-sanitisation.md) 用纯 CSS 实现。

## Considered Options

- **编译期把编号写死进 HTML**（生成 `<div>` 加一个装数字的元素）：布局最自由，圆圈可以放任何位置、可以带副标题。落选——失去「这是一个列表」的语义，读屏软件不会念「共 3 项，第 1 项」。
- **编译成 `<div>` 但用 CSS `counter-increment` 数**：布局自由、编号仍由浏览器算。落选——付了语义的代价，却没拿到编译期写死的那份自由度。

## Consequences

作者写的本来就是有序列表，编译成有序列表是最短的路径：不需要编号逻辑、不需要在编译期数数、作者在中间插入一个步骤时没有任何东西需要同步。

「无 JavaScript 时降级成什么」这个问题在这里不需要设计——有序列表本身就是完整可读的，编号和样式都来自 CSS 而非 JavaScript。关掉动效（`prefers-reduced-motion`）同样不影响编号。

代价是布局自由度受限于 `<ol>` 的结构。「每个步骤带一个副标题」这类需求需要在 `<li>` 内部用标题元素表达，而不是重新设计外层结构。
