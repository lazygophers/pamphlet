# 图表主题联动靠构建期后处理 SVG 颜色

引擎吐出 SVG 之后，编译器扫一遍，把硬编码的颜色替换成带兜底值的 CSS 变量：`fill="#2d6cdf"` → `fill="var(--pf-diagram-primary, #2d6cdf)"`。因此切换主题不需要重新渲染图表——这保住了原始设计的 FR-6。

**怎么保证不漏，用哨兵机制**：渲染时先把一组现实中不会出现的哨兵色（`#ff0001`…`#ff0006`）当作引擎的主题色喂进去，再在输出里把哨兵换成对应的 CSS 变量。这样「哪个颜色对应哪个 token」不靠人维护一张表，而是渲染前就定好的。输出里出现非哨兵的色值 = 引擎有硬编码，给一条 `DIAG-304` 警告把它报出来——那正是本 ADR 担心的静默失效的解药。

**只处理十六进制写法。** 为了让这一条成立，喂进去的哨兵必须是十六进制：实测证明这样能把引擎输出里的 CSS 具名色挤掉（默认主题下 Mermaid 的 `<style>` 里写的是 `fill:black`）。

## 为什么必须后处理

调研结果是四个引擎行为不同：

| 引擎 | 主题联动 | 证据 |
|---|---|---|
| Mermaid | **不支持**，需后处理 | `themeVariables` 不接受 `var(--x)`——sanitize 正则会清空非十六进制值。官方 open issue：mermaid-js/mermaid#6677、#6860（approved 未实现）。输出 SVG 内嵌 `<style>` 配硬编码十六进制。GitHub 官方也踩过：`orgs/community#12116` 确认 Mermaid 无法正确响应 `prefers-color-scheme: dark` |
| Graphviz | **不支持**，需后处理 | dot 颜色按具名颜色表解析，未知色名当错误处理并报 warning |
| d2 | **不支持**，需后处理 | 调研曾认为 d2 官方会内嵌 `@media (prefers-color-scheme: dark)`，**实测不成立**：默认参数下输出里没有这个块、没有 `currentColor`，同样是 12 个硬编码十六进制色值。d2 和 Mermaid 一样要走后处理 |
| MathJax v3 | **原生支持** | 官方默认输出 `currentColor`，公式颜色跟随周围文字色 |

## Considered Options

- **渲染两份**（亮色一份、暗色一份），CSS 隐藏其中一份：零替换规则、保真度 100%。落选：每张图的渲染时间和体积都翻倍，而图表渲染是整条管线最慢的一步（要启动无头浏览器）。
- **放弃「切主题不重编译」**，主题在编译时选定、去掉切换按钮：实现最简单。落选，与「暗黑模式跟随系统」这个用户故事直接冲突。

## Consequences

**兜底值是这个方案的安全网**：`var(--x, #2d6cdf)` 在变量没定义或替换漏掉时仍然给出原色，最坏情况是「颜色不跟主题变」而不是「图没有颜色」。

**实测确认这条路成立**：把 Mermaid 输出的色值换成 `var(--pf-diagram-*, #原色)` 之后，同一份 SVG 只改 CSS 变量，亮暗两套都正确渲染，不需要重新渲染图表。开销是 70 处替换、SVG 从 25942 涨到 27654 字节（+6.6%）。

**代价是持续的维护面**：引擎升级改了输出结构，替换可能失效。而实测踩到的那次失败说明了它的性质——只替十六进制时漏掉 `fill:black`，结果暗色下框内文字和背景同色，**不报任何错**。纯文本 golden 快照发现不了这个：快照只会显示「`fill:black` 还是 `fill:black`」，一切正常。

因此必要配套有两层，都不是可选项：

1. **`DIAG-304` 警告**：输出里出现非哨兵色值时报出来（引擎升级引入新硬编码色的信号）。
2. **对比度检查**：在真浏览器里渲染，取每个文字节点与其背景的实际颜色算对比度，低于 4.5:1 就失败，亮暗各跑一遍。这是唯一能自动接住「暗色下文字看不见」的手段。无头浏览器本来就是依赖，不引入新东西。

**主题切换按钮与记忆**：切换本身纯靠 CSS 类切换，所有浏览器都可用。「记住选择」用 localStorage，但整段包在 try/catch 里，失败静默降级为「不记忆」——因为 localStorage 在 `file://` 下三家浏览器行为不同：Firefox 完全阻塞（<https://bugzilla.mozilla.org/show_bug.cgi?id=507361>，故意设计）、Safari 11+ 抛 `SecurityError`（<https://developer.apple.com/forums/thread/87778>）、Chrome 可用（实测确认）。不给读者任何错误提示——他们对此无能为力，提示只是噪音。

后处理只在 SVG 内联时有效（用 `<img>` 引用会切断 CSS 继承链），这正是 Pamphlet 的架构，所以不构成额外约束。
