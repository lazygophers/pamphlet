# Tab 标题渲染成真实标题元素，进入文档大纲

每个 Tab 面板的标题渲染成真实的标题元素，层级取「最近祖先标题 + 1」，并带上由标题文本生成的锚点 id。有 JavaScript 时这些标题被隐藏、变成可点的 Tab 按钮；没有 JavaScript 时它们就是正常的小节标题，面板顺序展开。

例：一组 Tab 位于 `## 部署方案` 之下，两个 Tab 标题渲染为 `<h3 id="部署视图">` 和 `<h3 id="成本视图">`。

## Considered Options

- **渲染成粗体文字，不进文档大纲**：大纲保持干净，将来做目录时不会被一堆 Tab 标题淹没。落选：读屏软件用户失去在面板间跳转的能力，深链也无处可指。
- **每个面板渲染成 `<details open>`**：无 JavaScript 时用浏览器原生折叠，读者能自己收起看过的面板。落选：「Tab」和「折叠」两种指令的降级形态会变成同一个东西，读者分不出作者原本的意图，而且 `<summary>` 同样不进大纲。

## Consequences

Tab 面板在语义上确实是并列的小节——作者选 Tab 而不是小节，理由是「省地方」而不是「这些内容不重要」。渲染成真实标题让读屏软件导航、目录、页内搜索、深链这四件事同时得到正确行为，而不需要为每一件单独设计。

层级用「最近祖先标题 + 1」而不是固定值，是为了不在文档大纲里跳级——大纲跳级会被无障碍检查工具报为问题。

锚点 id 由标题文本生成（中文保留、空格转连字符）。同一份文档里标题重名时必须去重（追加 `-2`、`-3`），否则深链会指向错误的面板。

代价：将来做目录功能时，Tab 标题会出现在目录里。如果这变成问题，解法是给目录一个「跳过 Tab 标题」的选项，而不是回退本决定——因为回退会同时失去无障碍与深链。
