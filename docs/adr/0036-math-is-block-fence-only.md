# 数学公式只做块级 `math` 围栏，不支持行内 `$...$`

公式写在 ` ```math ` 围栏里，构建期由 MathJax v3 预渲染为 SVG（见 [0008](./0008-builtin-engines.md)）。**不支持行内公式语法 `$E=mc^2$`。**

## Considered Options

- **支持 `$...$` 行内公式**：这是 LaTeX 生态的通行写法，很多人有肌肉记忆。落选，两个原因：一，它是 CommonMark 之外的**新增行内语法**，而本项目的语法扩展一直只走指令与围栏两条路（见 [0013](./0013-tab-syntax-is-nested-directives.md)、[0019](./0019-fence-names-are-engine-native.md)）；二，`$` 在技术文档里出现频率很高——shell 提示符（`$ npm install`）、环境变量（`$HOME`）、货币（`$99`），支持它必须同时设计冲突判定和转义规则，而误判会把一段正常文字变成公式。

## Consequences

行内的数学表达只能退回三条路：写在块级围栏里（哪怕只有一个符号）、用裸 HTML 的 `<sub>` / `<sup>`（[0021](./0021-raw-html-passes-through-untouched.md) 让裸 HTML 原样通过，所以这条现在是可用的）、或者接受纯文字写法（`H2O`）。

对技术方案文档这个目标场景，损失不大——那里的公式通常是复杂度分析或容量估算，本来就适合独占一行。

如果日后要加行内公式，正确的做法是走文本指令（`:math[E=mc^2]`）而不是 `$...$`：前者不新增语法规则、没有冲突和转义问题，代价只是写起来长一点。
