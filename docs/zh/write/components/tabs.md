# 标签页（Tab）

## 这是什么

同一个话题的**几种视角**，读者点一下切换，一次只看见一种。

比如同一套方案的「部署视图 / 成本视图 / 风险视图」，或者同一条命令的 macOS / Linux 两种写法。

**不是**用来放几件不相干的事——那是[标题](/write/text/headings)该干的活。

## 怎么写

```markdown
::::tabs

:::tab[部署视图]{default}
两个可用区，每区三台。
:::

:::tab[成本视图]
月成本约 ¥3,200。
:::

::::
```

| 指令 | 指令标题 | 属性 |
|---|---|---|
| `tabs` | — | 不接受 |
| `tab` | **必填** | `default` |

### 四条规则

- **外层冒号必须比内层多**：`::::tabs` 包 `:::tab`。一样多会报 `DIR-202`——第一个 `:::` 就把外层关掉了
- **`tab` 的指令标题必填**：它就是那个可以点的按钮，没有就没有可点的东西，报 `DIR-204`
- **`tabs` 里至少要有一个 `tab`**，空的报 `DIR-204`
- **`tab` 只能直接放在 `tabs` 里**，放在别处报 `DIR-202`

### `{default}` 只能有一个

标了两个以上报 `DIR-205`；都不标时选中第一个。

:::info 为什么报错而不是取第一个
静默猜测会产出和你意图不同的产物——你以为默认打开的是「成本视图」，读者看到的却是「部署视图」，而没有任何提示。
:::

## 出来是什么样

一排可点的按钮加一块面板。按钮样式由主题决定：`editorial` 是报头式，`console` 是分段控件，`manual` 是文件夹标签。

**关掉 JavaScript 时三个面板全部展开**，每个 `tab` 的指令标题降级成一个普通小节标题，一个字都不丢。这是设计的出发点而不是补丁。

## 坑

- **几个面板的内容长度要差不多**。一个三行、另一个三屏，读者会以为短的那个没写完
- **别用它藏关键信息**：关掉 JavaScript 就全展开了，内容一直在 DOM 里
- Tab 的指令标题为了无障碍和深链被做成**真标题**，会进文档大纲——所以目录默认跳过它们（`toc.skipTabs`，缺省 `true`）
