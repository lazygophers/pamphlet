# 表格

## 这是什么

行和列组成的数据网格：比参数、比方案、列字段、列成本。

**Markdown 的表格只能装简单内容**——它不是电子表格，没有合并单元格，也放不下段落。

## 怎么写

```markdown
| 环境 | 实例数 | 月成本 |
|---|---|---|
| 生产 | 6 | ¥3,200 |
| 预发 | 2 | ¥800 |
```

三部分：**表头一行、分隔行、若干数据行**。分隔行是必须的，没有它就不是表格。竖线两侧的空格随意，不用对齐（对齐只是为了源文档好读）。

## 每列怎么对齐

在分隔行那一格里加冒号：

```markdown
| 左对齐 | 右对齐 | 居中 |
| :--- | ---: | :---: |
| 甲 | 1,200 | 是 |
| 乙 | 980 | 否 |
```

| 分隔行写法 | 效果 |
|---|---|
| `---` | 缺省，左对齐 |
| `:---` | 左对齐 |
| `---:` | **右对齐**，数字列该用这个 |
| `:---:` | 居中 |

## 单元格里能写什么

行内的东西都能写：粗体、`行内代码`、链接、图片。

**放不下块级的东西**：代码块、列表、多个段落。真要放，挪到表格外面，或者改用[折叠块](/write/components/collapse)。

内容里要写竖线 `|` 时**转义成 `\|`**，否则会被当成列分隔符。

## 没有合并单元格

GFM 表格**不支持跨行跨列合并**，也没有多层表头。需要合并的表格，通常意味着它该拆成两张。

## 出来是什么样

主题之间差别很大：

| 主题 | 表格长什么样 |
|---|---|
| `default` | 表头带底色，全边框 |
| `paper` `architecture` | **三线表**：只有顶部、表头下、底部三条线 |
| `manual` | 表头吸顶 + 斑马纹，为长表格设计 |
| `console` | 高密度，行高很紧 |

窄屏上表格**横向滚动，不挤压换行**。

## 坑

- 数字列记得用 `---:` 右对齐，否则位数对不齐、看不出大小
- 表格里写不下就别硬塞：三列以上的长文字表格在手机上几乎不可读
