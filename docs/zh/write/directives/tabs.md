# 标签页

同一个话题的几种视角，读者点一下切换。

```markdown
::::tabs

:::tab[部署视图]{default}
两个可用区，互为主备。
:::

:::tab[成本视图]
月成本约 ¥3,200。
:::

::::
```

| 指令 | 标题 | 属性 |
|---|---|---|
| `tabs` | — | 不接受任何属性 |
| `tab` | **必填** | `default` |

## 四条规则

- **外层冒号必须比内层多。** `::::tabs` 包 `:::tab`。写成一样多会报 `DIR-202`
- **`tab` 的标题必填。** 它就是那个可以点的按钮，没标题就没有可点的东西 —— 报 `DIR-204`
- **`tabs` 里至少要有一个 `tab`。** 空的报 `DIR-204`
- **`tab` 只能直接放在 `tabs` 里。** 放在别处报 `DIR-202`

## `{default}` 只能有一个

同一组里标了两个以上报 `DIR-205`。都不标时选中第一个。

:::info 为什么报错而不是取第一个
静默猜测会产出和你意图不同的产物 —— 你以为默认打开的是「成本视图」，读者看到的却是「部署视图」，而没有任何提示。
:::

## 关掉 JavaScript 时

**三个面板全部展开，一个字不丢。** 每个 `tab` 的标题降级成一个普通小节标题。

这是设计的出发点而不是补丁：Tab 先有一个不依赖脚本的形态（全部展开的几个小节），再往上叠切换脚本。

## 目录里默认看不到 Tab 标题

Tab 标题为了无障碍和深链被做成了**真标题**，所以注定会进文档大纲。但它们在语义上是「同一话题的几种视角」，出现在目录里会让读者以为是不同章节。

所以 `toc.skipTabs` 缺省是 `true`，见 [frontmatter 参考](/reference/frontmatter)。
